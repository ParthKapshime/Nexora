ProductNexora, an AI-powered career guidance and skill-development platform. AGENTS.md is the primary project guidance.

Technical decisions

DecisionReason and alternativesApproval
Use CommonJS JavaScript and ExpressMatches existing .js placeholders and the approved backend stack. No language or framework change.Explicitly specified.
Use MongoDB/Mongoose with database NexoraConnection is environment-driven and enforces the required database path. No credentials are hardcoded. Real connection is blocked pending a rotated URI in ignored local backend/.env.Explicitly specified.

Zod 4.6.7 validationValidates bodies, parameters and queries. Initial install audit identified a high severity issue in Zod 3, so the dependency was upgraded and re-audited.Zod explicitly specified; secure version selected during implementation.
HTTP securityHelmet/CSP, production HSTS, allowlist CORS, body size cap, Mongo operator sanitization, global/auth/upload rate limits, private upload storage, request IDs, and safe errors. In-process rate limits need a shared store before multi-instance deployment.Security protections explicitly required; shared store depends on deployment setup.
Resume upload and parsingPDF MIME/extension allowlist, 5 MiB cap, server-generated names, PDF signature check, and private ignored storage. pdfjs-dist 6.4.299 extracts selectable text on upload with a 30-page limit, 50,000 stored characters, and a 15-second timeout. This raises the backend runtime floor to Node 22.13+. Encrypted or unreadable PDFs are rejected; scanned PDFs are accepted with parseStatus: "no_text". Text is excluded from API responses by default and included in AI prompts only when available. No OCR is implemented.User selected pdfjs-dist; secure upload explicitly required.
User data resourcesSkills, roadmaps, projects and interview records store authenticated-user content. AI-generated roadmaps and project ideas are returned to the UI and are not saved until the user explicitly saves them. Interview sessions store generated questions, submitted answers, per-answer feedback, progress and average score, scoped to their owner. Readiness is stored on the profile after analysis.Required modules implemented; generation results remain distinguishable from user-authored records.
AI provider integrationOpenAI-compatible Hugging Face Router is used for chat completion and the career AI endpoints at POST /api/ai/analyze-skills, /roadmap/generate, /projects/recommend, /interviews/start, and /interviews/:id/answer. The model is Qwen/Qwen3.8-27B:novita unless overridden by HF_MODEL. Responses are parsed and Zod-validated; malformed output is retried once then reported as 502, timeouts as 504, and missing configuration/unavailability as 503. All routes are authenticated and rate-limited, with safe errors and no silent provider fallback. Live provider execution requires HF_TOKEN; no token is committed.Explicit user request for Hugging Face; project guidance updated to match.
OpenAPI/SwaggerCanonical OpenAPI 3 spec is served at /openapi.json, Swagger UI at /api-docs, and generated static JSON at backend/openapi.json for Thunder Client import.Explicitly requested.
Git repository setupRoot Git repository and supplied origin were configured after the user approved it. An empty nested backend/.git (no refs, objects, commits or remote) was preserved under an ignored backup name to prevent accidental gitlink staging.Approved by user.
HTTPSLocal development stays HTTP. HSTS is enabled in production mode; actual TLS and HTTP-to-HTTPS redirect require a future deployment reverse proxy/certificate.HTTPS readiness explicitly required; no deployment target selected.

  • Resume text extraction is implemented with pdfjs-dist. Scanned/image-only PDFs produce parseStatus: "no_text"; OCR is not implemented.
  • Before scaling beyond one server process, configure a shared rate-limit store.
  • Thunder Client tests remain unrun. Import backend/openapi.json after local environment configuration.
  • Production push verification completed for the initial backend commits; subsequent changes must continue using the same remote and normal fast-forward pushes.
