# Nexora project decisions

## 2026-10-31 — Frontend implementation

- The app uses React, JavaScript, Vite, and React Router in `frontend/`, following the current `AGENTS.md`. Authenticated pages share one responsive shell and the warm light visual system from `docs/references/nexora-ui-workflow-reference.png`.
- Browser requests go through the Express REST API. The browser never connects to MongoDB or directly to an AI provider. With `VITE_API_BASE_URL` unset, browser calls use same-origin `/api` paths and Vite proxies them to the local Express service. The proxy rewrites the upstream Origin to the backend's existing localhost CORS origin so forwarded frontend requests can use the existing API without backend changes. Browser-exposed environment variables must never contain secrets.
- Frontend integration covers auth, profile and PDF resume operations, user-authored skill/roadmap/project records, job applications, AI career features, and the Express chat-completions route.
- Readiness and profile completion display only values derived from returned data. The UI does not invent assessment results or AI-generated records.
- E2E browser fixtures are synthetic and intercepted in Playwright; they do not write to MongoDB. Live auth and data workflows still need validation with a dedicated test account.
- Verification on 2026-10-31: `npm run lint` passed; `npm test` passed (3 files, 8 tests); `npm run build` passed; `npm run test:e2e` passed (7 Chromium tests, one worker), including desktop/tablet/mobile layout, unauthenticated access, backend outage handling, and empty records. A read-only request through the Vite proxy with the forwarded-site Origin returned the expected backend 401 and CORS headers. No registration or account data was submitted.

## 2026-10-31 — AI career features and provider alignment

- **Provider:** Hugging Face Inference Providers through the OpenAI-compatible router is the only AI provider. The backend uses server-side `HF_TOKEN` and the configured `HF_MODEL`; the browser never contacts Hugging Face. `AGENTS.md`, this file, `test.md`, and `decision.html` now consistently describe Hugging Face. No Ollama, Gemini, or OpenAI-hosted provider is added, and there is no silent provider fallback.
- **Implemented endpoints:** `POST /api/ai/analyze-skills`, `/api/ai/roadmap/generate`, `/api/ai/projects/recommend`, `/api/ai/interviews/start`, and `/api/ai/interviews/:id/answer` now call Hugging Face with prompts built from the authenticated user's saved profile and skills. The old "AI functionality is currently unavailable" stubs were removed.
- **Structured output:** AI responses are parsed as JSON (fenced output accepted) and validated with Zod schemas. Malformed provider output is retried once, then reported as `502`; provider timeouts map to `504`; missing configuration or upstream unavailability maps to `503`. The frontend shows safe, actionable messages and never displays provider internals.
- **Data handling:** Skill analysis stores its AI-assisted readiness estimate in `profile.readiness` (`score`, `summary`, `targetRole`, `updatedAt`). Generated roadmaps and project ideas are returned to the UI and are not written to user lists until the user explicitly saves them. Mock interviews are stored as owner-scoped `UserResource` records with questions, answers, per-answer feedback, progress, and average score. Manual CRUD records remain user-authored content, not AI output.
- **Limits:** Requests require a target role and at least one saved skill. AI routes share a 60-request/15-minute authenticated limiter.
- **Resume parsing:** `pdfjs-dist` 6.4.299 (legacy Node build) extracts selectable text on upload. This raises the backend runtime floor to Node 22.13+ (the verified runtime remains Node 24.13). Parsing is bounded to 30 pages and 50,000 stored characters with a 15-second timeout; encrypted or unreadable PDFs are rejected, while scanned PDFs are accepted with `parseStatus: "no_text"`. Extracted text is stored with `select: false`, never returned by the API, and included only in AI career prompts when available. Scanned resumes do not use OCR.
- **Documentation correction:** The JWT access-token TTL is 300 seconds (5 minutes) in the implementation and OpenAPI schema. `test.md` and `decision.html` previously said one hour; both now record 300 seconds.
- **Verification on 2026-10-31:** Backend `npm run check` passed (50 passed, 1 opt-in live database test skipped, 0 failures); `npm run openapi` regenerated `backend/openapi.json`; `npm audit --audit-level=low` reported 0 vulnerabilities. Frontend `npm run lint`, `npm test` (8 tests), `npm run build`, and `npm run test:e2e` (7 Chromium tests) passed. Automated AI tests mock the Hugging Face client. No live Hugging Face provider request or real-resume upload was sent, so model access, latency, and production PDF handling remain unverified.
